摘要

教师模型生成的推理链与 SQL 经真实数据库执行验证，保留 5783 条用于 Qwen3-8B 全参数监督微调；再由微调模型自采样构造 7989 对偏好数据做偏好对齐。BIRD 开发集全量 1534 题执行准确率由 46.68% 升至 65.45%，收益全部固化在权重内，推理为单次调用、无流水线。

1. 项目背景

自然语言取数是商业智能（Business Intelligence, BI）场景中的一类垂直指令任务：用户用中文或英文提问，系统需要在给定数据库上生成一条能真正跑出正确结果的 SQL。它与通用对话任务的差别在于，正确与否可以被客观判定——把 SQL 放到真实数据库里执行，与标准答案的结果集比对即可，无需人工标注，也无需大模型评判。

立项前先测了两件事，用来判断这个题目值不值得投入算力。

第一，基座模型确实不够用。Qwen3-8B 在 BIRD 开发集（11 个真实业务库、1534 题）上零样本直出 SQL 的执行准确率（Execution Accuracy, EX）只有 46.68%，语法有效率 84.22%。这些库不是玩具库：financial（银行交易，8 表 68 MB）、thrombosis_prediction（医院检验，3 表 64 列）、european_football_2（570 MB）。

第二，提示词工程能把分数拉高，但代价不可接受。系统做了十余组免训练消融（表 1）。最强的可部署免训练配置是「打开原生思考模式 + 用标准建表语句表示 schema」，执行准确率 59.97%，但同一张 A100 上跑完 1534 题需要 1048.7 秒，是基准配置的 19.5 倍（成本细节见第 8 节）。商业智能取数是交互式场景，用户不会为一次取数等 20 倍延迟。

此外，两项前置诊断否掉了原方案里的一条支线：BIRD 开发集平均只有 6.8 张表、提示词长度中位数 2544 token，词面 schema 链接只省下约 4% 的 token 却带来 1.3% 的漏表率，因此砍掉 schema 链接，只保留预言机链接作为上界诊断。基座模型上每题采样 8 条按结果集聚类投票只有 47.91%（p=0.427，不显著），而「8 次中至少对一次」为 51.76%——采样上界过低，说明强化学习必须排在监督微调之后。

2. 任务目标

目标是只优化模型自身，把上述提示词工程能拿到的收益固化进 80 亿参数的权重里，使模型在单次推理下达到甚至超过免训练最强配置的精度，同时把推理成本拉回可交互的量级。

2.1 输入与输出

输入 = 自然语言问题
     + 数据库 schema（M-Schema 表示：表名、列名、类型、主键，
                      每列附 3 个去重后的真实样例值）
     + 外部知识提示（BIRD 的 evidence 字段，90.4% 的题目带有）

输出 = 推理过程 + 一条可直接在该数据库上执行的 SQL

2.2 约束

  • 只优化模型本身：所有提升必须固化在一份 8B 权重里，不引入检索器、选择器、投票器等外部组件。
  • 单次推理：头条数字只取贪心解码、一次调用的结果；多轮重试、多次采样投票即使有效也单独报告，不并入主线（第 7.5 节）。
  • 评测口径统一且不可事后调整：主指标为执行准确率，真实执行 SQL 并按 BIRD 官方的结果集集合语义比对；全量 1534 题不抽样；所有提升做配对麦克尼马尔精确检验（McNemar's exact test）与配对自助法 95% 置信区间；p ≥ 0.05 的结果显式标注为不可引用；零人工标注、零大模型评判。

2.3 形式化定义

任务。给定自然语言问题 q、数据库模式 S = {T1, …, Tm}（每张表含列名、类型、主外键与若干真实样例值）以及外部知识提示 e，模型 πθ 需生成一条 SQL 查询 y：

y ~ πθ( · | x ),    x = Prompt( q, S, e )

评价函数。设 D 为目标数据库，Exec(y, D) 为执行 y 得到的结果集，y★ 为标注 SQL。执行匹配的指示函数定义为

𝟙EX(y) = 1，当且仅当 Set( Exec(y, D) ) = Set( Exec(y★, D) )；否则为 0
（执行报错、超时均计为 0）

执行准确率即该指示函数在评测集上的均值：EX = (1/N) Σi 𝟙EX(yi)。采用集合语义而非逐行比较，与 BIRD 官方口径一致，代价是对行序不敏感（见第 9.4 节）。

优化目标与约束。

maxθ  E(q,S,e) [ 𝟙EX(y) ]    s.t. y ~ πθ( · | x )，单次采样，|θ| = 8 × 109

约束的实质含义是：不允许多次采样投票、不允许执行反馈重试、不允许外部检索或流水线编排，所有性能提升必须体现在权重 θ 内。

可验证蒸馏。设教师模型 πT 对训练问题 xi 生成推理过程与查询 (ci, yi)。构造训练集时施加执行一致性约束：

DSFT = { (xi, ci, yi) : 𝟙EX(yi) = 1 }

与常规思维链蒸馏 D = {(xi, ci, yi)} 的区别在于：过滤信号来自环境执行结果而非模型自评，因而能够识别「语法正确、逻辑自洽、但答非所问」的样本。监督目标为自回归交叉熵，且仅在回答段计算损失：

LSFT(θ) = − Σt ∈ Ans log πθ( zt | z<t )

其中 Ans 为回答段的 token 下标集合。提示词段（数据库模式约 2500 token）占序列的绝大部分，实测参与损失的 token 仅占 15.50%；若不做掩码，损失将主要由「复述数据库模式」贡献。

偏好优化。以监督微调后的模型对每个训练问题采样 K = 16 条候选，按执行结果划分为正例集与负例集：

Y+i = { y : 𝟙EX(y) = 1 }，   Y−i = { y : 𝟙EX(y) = 0 }

仅当两个集合均非空时该问题可用（实测可用率 28.54%）。正例取执行正确者中最短的一条；负例的选取方式是本项目的对照变量：

y−相似 = arg maxy ∈ Y− sim( y, y+ )，   y−相异 = arg miny ∈ Y− sim( y, y+ )

直接偏好优化的损失如下，其中参考模型 πref 取监督微调后的模型而非原始基座（理由见第 6.2 节），对数似然同样只在回答段累加：

LDPO = − log σ ( β [ log πθ(y+|x) / πref(y+|x) − log πθ(y−|x) / πref(y−|x) ] )

3. 流水线总览

整条链路是：基座模型 → 可验证蒸馏构造数据 → 全参数监督微调（Supervised Fine-Tuning, SFT）→ 直接偏好优化（Direct Preference Optimization, DPO）→ 执行式评测。每一步的产出与关键数字见图 1。

5. 数据构造：可验证蒸馏

5.1 教师模型能力校准

用教师模型生成数据之前先测教师自己有多强。首次测得执行准确率仅 50.0%，且 24% 的调用完全不输出 SQL。抽查 150 条后定位到与前述 A7 完全同类的缺陷：无 SQL 的 36 条推理链平均 8634 字符，正好顶到 2048 的预算上限，答案 0 字符；有 SQL 的 114 条推理链平均 2827 字符、答案 196 字符。把预算放宽到 8192 后，截断率 24% → 2.67%，教师执行准确率 50.0% → 60.67%，语法有效率 96.13%。

这次校准的价值不在于把分数修回来，而在于：被截断的恰好是最难的题。不查就直接用，蒸馏集会系统性缺失难样本，而这种缺失在数据里看不出来——它长得就像「教师答不上来」。

5.2 全量蒸馏与执行过滤

教师对 BIRD 训练集逐题生成（推理链, SQL），随后在真实数据库上执行，结果集与标准答案一致才入库。9428 题原始数据中，有 350 题的标准答案自身就跑不通（3.7%，无法验证，予以排除并显式报告），可蒸馏基数为 9078 题，最终保留 5783 条（63.70%）。API 用量为提示词 1572 万 token + 生成 415 万 token（其中推理占 94%），120 并发下墙钟 651 秒。

9. 阴性结果与局限

这一节记录失败与不显著的部分。项目内所有 p ≥ 0.05 的结果由脚本自动标注为「不可引用」，以避免事后挑数字。

9.1 一次值得记录的误判

第一轮偏好优化的结果与基座逐字相同（Δ=+0.00，p=1.0）。当时的第一反应是归因于「偏好优化的目标与执行准确率结构性脱节」——它优化的是两条固定字符串的相对排序，而执行准确率取决于贪心解码出的那一条。为了验证这个归因，在同一批偏好对上分别用基座与训练后模型打分：92.5% 的贪心输出逐字未变，但正负例的排序间隔从 0.67 涨到 4.81。排序确实被拉开了，只是幅度不足以改变贪心解码的结果。真正的原因是训练强度不足（60 步 × 5e-7），而不是算法选错。没有这个诊断，就会去换算法，换完还是不动，再换下一个，永远找不到真因。

同期另一起事故：观察到损失稳定在 11.06（理论初值应为 ln2 ≈ 0.693），一度以为训练发散，实际是读错了日志——11.06 ≈ 0.693 × 16，是梯度累积的展示求和。教训是怀疑数值异常时，也要查产生这个数字的显示逻辑。

10.1 评测器先于一切

项目的第一件事是把尺子造准：用标准答案当作预测跑自检，1219 题中 1218 题通过（99.92%）；唯一未通过项追到底是标准答案自身需要跑 128 秒触发超时，不是评测器的缺陷，因此已知的不可达上界为 0.08%。据此修正超时口径后，在全量 1534 题上重跑自检得到 100.0%，评测器本身不再引入误差。这次自检一次性暴露了三类隐藏问题：超时语义、标准答案数据质量、SQL 抽取逻辑。超时刻意设置为不对称——预测 SQL 30 秒、标准答案 300 秒，方向是对模型更严。

数据获取环节做了两道校验：按服务端返回的 Content-Length 精确校验字节数（只判「文件非空」会把中断产生的截断文件误认为完成）；从两个独立来源各下载一份开发集，对（题号, 库名, 问题, 归一化 SQL）计算 SHA-256，结果逐题完全一致。

10.2 训练前的三层验证

一次失败的六卡训练要浪费 1.5 小时，因此每次训练前按三层递进验证：零件级（纯 CPU，不训练；验证损失掩码、截断率、提示词一致性）→ 代码级（2 卡 + SGD 优化器，跑通完整训练循环与数据分片）→ 生产级（4 卡真实配置跑 4 步，看显存余量）。

10.3 共享集群上的调度经验

显卡数与 CPU 核心数是两个独立配额，只按显卡数算并发度会让一半算力闲置：

训练分区配额：6 GPU + 48 CPU 核（两个独立维度）

  --cpus-per-gpu=16 × 3 GPU = 48 核  →  CPU 配额用尽，剩余 3 张卡无法并发
  --cpus-per-gpu=8  × 3 GPU = 24 核  →  两个 3 卡作业可同时跑满

另一条经验是减少作业数比减少计算量更值钱：vLLM 加载一次 80 亿参数模型需 6.5 分钟（文件系统争用时可达 9 分钟），十余组免训练消融若拆成 10 个作业，光加载开销就是 65 分钟外加 10 次排队，因此合并为一个作业循环跑完。

10.4 沉淀下来的工程纪律

  • 混合推理模型的 token 预算必须按「推理链 + 答案」一起算——同一类截断缺陷在本项目里犯了两次（A7 与教师校准）。
  • 训练端与评测端共用同一份提示词代码，否则蒸馏出的推理链会引用学生看不到的信息，等于训练时教模型编造。
  • 改显卡数必须同步改梯度累积，锁死有效批量；4 卡 × 8 与 6 卡 × 8 是两个不同的训练配置。
  • 训练中途就要保存检查点——低秩适配那次训完 1 小时 39 分，崩在最后一步保存，检查点目录全空。
  • 单样本训练日志不能用来下任何结论；怀疑数值异常时，先查产生这个数字的显示逻辑。
  • 按数据库编号而不是按题目划分训练与验证集，否则同库 schema 与取值会造成泄漏。

11. 后续工作

  • 推理链的正确性验证。可验证蒸馏只校验了答案，没有校验推理过程；下一步计划对训练集做人工抽检，量化"推理写错但 SQL 恰好正确"的比例。
  • 训练前置于思考模式之上的可能性。本项目的偏好数据构造在关闭思考模式的模型上进行；若在思考模式输出上构造偏好对，采样与训练成本约为当前的三倍以上，受算力预算限制未做，属于未验证的对照而非已证无效的方案。
  • 教师答错的 3295 条难题仍是未利用的存量，需要与「多采样」和「反向合理化」都不同的第三条路线。

附录 B：可迁移的原理

以下八条是从本项目的具体实验中抽象出的一般性结论，每条都给出本项目内的实测依据。它们的适用范围不限于 Text2SQL。

表 B1：从实验中提炼的一般性结论及其实测依据。
原理实测依据
一、环境反馈优于模型自评在具备可执行环境的任务上，数据过滤应使用环境返回的确定性信号。被过滤样本中 89.3% 属于「可正常执行但返回结果错误」，此类样本语法正确、推理自洽，模型打分难以识别。
二、基于模型能力的数据过滤必然引入难度偏置凡以「模型能否做对」为准则的筛选——执行过滤、拒绝采样、自训练、强化学习的样本选择——都会系统性保留简单样本。实测保留率简单 70.0%、中等 58.8%、困难 49.1%，训练集较原始分布偏简单 5.4 个百分点。该偏置在数据中不可见，必须显式量化。
三、模仿学习的上限是教师本身监督微调的性能受限于教师能力（本项目教师为 60.67%）。若目标高于该水平，必须引入不依赖教师的信号；本项目用模型自采样加执行验证构造偏好数据，最终达到 65.45%，超过教师。
四、推理过程是「用推理时算力换训练数据」的手段数据受限时（5000 条），推理过程监督带来 2.87 个百分点的显著提升；数据充足时（全量），其效果与增加直出样本相当，而推理成本高约 5 倍。推理链的价值随数据量增加而衰减，因此消融必须在多个数据规模上进行。
五、混合推理模型的生成预算由推理过程与答案共享预算不足时推理过程会耗尽额度导致答案缺失，且被截断的恰好是最难的样本，表现形式与「模型能力不足」完全相同。该缺陷在教师侧与学生侧各出现一次，修正后教师执行准确率由 50.0% 升至 60.67%。
六、排序改善不等于贪心解码结果改变偏好优化作用于两条固定候选的相对排序，而评测指标取决于贪心解码输出。实测偏好间隔由 0.67 增至 4.81，但 92.5% 的贪心输出逐字未变。判断偏好优化是否生效必须在固定数据集上聚合测量，不能依据训练日志。
七、强化学习的可行空间由采样上界决定若样本在多次采样下全部错误，奖励恒为零、组内优势恒为零、梯度为零。基座采样 8 次至少对一次的比例为 51.76%，监督微调后升至 74.19%。「先监督微调、后偏好优化」的顺序是数据约束而非经验选择。
八、推理能力一旦内化，外挂推理即为冗余训练前开启思考模式值 13.29 个百分点；训练后值 0 个百分点（p = 1.0000），而推理开销增加 69%。同一份能力，训练前需每次现场生成 5281 字符换取，训练后 1365 字符即达更高水平。

本页所有数字均来自本人在 BIRD 开发集全量 1534 题与 Spider 开发集 1034 题上的实测结果；显著性统一采用配对麦克尼马尔精确检验，p ≥ 0.05 的结果在文中显式标注为不可引用。数据集为公开基准，算力为校级 GPU 集群，方案设计、代码实现、实验与分析均由本人独立完成。
